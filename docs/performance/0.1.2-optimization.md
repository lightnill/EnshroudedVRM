# 0.1.2 optimization measurements

The user-approved r11 inertial hair solver and native skinning shaders are
unchanged by the optimization. GPU skinning was already active. The main wins
come from removing repeated CPU setup and Vulkan resource allocation work.

| Isolated operation | Before | After |
| --- | ---: | ---: |
| Skeleton pose update, mean | 1.1509 ms | 0.0551 ms |
| GPU frame resource creation, warm median | 0.389 ms | 0.003 ms |
| GPU frame resource retirement, warm median | 0.856 ms | 0.001 ms |

These are local Windows x64 microbenchmarks, not game frame times. Do not sum
them with overlapping telemetry or translate them into an asserted FPS gain.
The pose benchmark measured 2000 changing updates after 200 warm-up samples on
a 201-node rig; input/output data remain private. Both paths produced the same
aggregate checksum. The GPU resource benchmark used synthetic 240k-vertex data;
8-batch and 480k-vertex controls also retained the warm allocation reduction.
Skin/finalize shader work stayed approximately 0.09 ms in that workload. Warm
allocation, mapping, descriptor pool/set allocation and destruction calls became
zero per retired frame; descriptor contents are still rewritten each frame.

## Implementation

Each view owns a compiled rig-metadata snapshot, excluding vertices/textures.
Static rig validation, topology, source-rest calibration, alignments and inverse
binds are cached only while exact rest bytes, options and semantic availability
match. Dynamic matrices, including unmapped source semantics, are always checked.
Errors construct diagnostics only on the failure path. The one-shot API remains.
New views validate locally before admission so rejected poses cannot evict the
four retained spring/contact histories.

GPU caches own raw buffer leases and descriptor packs. Only idle exact-key
matches are acquired; frame/history ownership prevents output reuse. Reused
mapped storage is cleared and all descriptors rewritten. The cache is bounded
to 128 buffers / 128 MiB actual reserved memory and 32 descriptor packs, counting
against the existing 512 MiB aggregate budget. Budget eviction touches idle
resources only. Quarantine and partial-allocation failure behavior are retained.

Further GPU precomposition was deferred: its remaining work is small and moving
it adds dispatch/synchronization while changing rounding and nonunit-weight
translation behavior. Spring solving is a small sequential CPU workload; data
transfer/readback would need to beat that cost before migration is useful.
Per-submission ownership/compatibility reads and deadlines are unchanged.

## Verification

The public fixtures cover 14 retarget-cache groups, actual renderer admission
methods at a synthetic boundary, 20 production GPU shader scenarios, seven GPU
reuse/lifetime/fault groups and 96 spring scenarios. The existing 31 retarget
cases passed. A separate old-source comparison checked 600 changing poses with
bit-identical node/palette matrices and errors in both new APIs. Local private
idle/running/stopped node and palette outputs also equal r11 exactly at the saved
checkpoints, with running/blocking clearance checks at 25/60/120 FPS.

The final source-only review found a rejected-view eviction issue, corrected
with a regression observed failing before the fix and passing afterward. The
full supported suite then passed: 15 programs, 98 Python checks; one optional
Windows link-privilege case was skipped. No new gameplay FPS measurement or
optimized-build visual verification was performed. Existing short-head-strand
jitter under combined running/blocking remains. See BUILDING.md for public
fixture commands. No private models, poses, textures, captures or traces are
published, and no third-party implementation code was borrowed for this pass.
