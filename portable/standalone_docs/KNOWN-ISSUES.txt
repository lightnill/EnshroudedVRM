FOG, OWNERSHIP AND PERFORMANCE
0.3.2 replaces the old fog snapshot extent restriction with a packed snapshot
and checked actual allocation requirements, keeping the 64 MiB budget. A driver
format/allocation limit can still decline replacement. Do not remove the budget.
World ownership uses the explicit local-player selector and validated entity.
Local inventory previews carry their own request/task/captured-pose association;
survivor or unresolved subjects retain native models. Desktop checks passed
inventory/survivor/inventory, equipment and title/character reload. This is not
an all-scene/all-hardware guarantee. Source and context changes can intentionally
decline replacement until fresh valid evidence is available.
Large models can reduce FPS. Voxel-base stutters remain; they were reduced but
not eliminated with the entire mod disabled. Local sampled CPU hook timings
help investigate this. Scopes overlap and cannot be added as frame time; sparse
samples can miss events/patterns and do not measure GPU duration. No gameplay
FPS improvement is claimed. The original 250 ms pose limit and fresh owner
verification remain; an expired pose is not held just to hide a fallback.

INSTALLATION AND STARTUP
An existing vulkan-1.dll from another mod is a conflict. Do not overwrite,
rename or chain it. Only update a known EnshroudedVRM installation while the
game is closed. Never copy a Windows system DLL into the game directory.
A previously loaded system Vulkan loader or System32-only loading can bypass
the game-local bootstrap. Nondefault Windows directories are unsupported.
EML/ShroudForge observations for the old script route do not validate this
standalone route. No multiplayer avatar synchronization is implemented.
Administrator launches or explicit Vulkan layer overrides may prevent startup;
those settings are respected. Network/linked paths and paths containing
semicolons are declined. Use an ordinary local installation and Steam launch.

Exact package/game checks precede optional hooks. Game updates or changed files
can disable replacement while retaining the original character. Do not bypass
compatibility checks. A layer manifest is held read-only until exit; close the
game before replacing mod files. Unrelated Runtime JSON files are not exposed.
No runtime entry means no F8 and possibly no fresh log. Treat only the current
session marker as current evidence. Startup history and runtime logs are bounded.
If package validation fails after runtime entry, only a fresh private diagnostic
is attempted; preference import/services do not start just to report that error.

SETTINGS, VOICE AND MODELS
One running game instance is supported. Settings are saved atomically under
%LOCALAPPDATA%/EnshroudedVRM/State. Unavailable storage uses safe defaults and
reports a save warning; administrator access is not requested. Existing model,
material and voice limitations remain. Game voice needs an online-capable
session with voice active; Local microphone works offline independently of
game mute/PTT. Capture is opt-in; microphone audio is not recorded or uploaded.
Embedded 16-bit PNG textures are normalized to RGBA8; large images can still
exceed the checked temporary decode-workspace limits. Full MToon and native
armor fitting remain future work. Use F8 Game lighting/Matte and per-material
presets to tune appearance.

DEBUG REPORTS
F8 creates a local allowlisted ZIP; nothing is uploaded automatically. Fresh
qualified Enshrouded XYZ coordinates use Y up and X/Z horizontal. Real-world
location, actual voxel data, saves, personal paths, account/server identifiers,
raw logs/settings, endpoint IDs, audio, models and memory dumps are omitted.
Screenshots are off per report; preview and explicit inclusion are required.
An included game image can show visible names/chat. Review before sharing.
The text-only path has desktop manual evidence. Optional screenshot capture,
map-coordinate interpretation and different hardware need broader manual tests.
